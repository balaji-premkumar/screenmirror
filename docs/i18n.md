# Adding a language

Four catalogs, none of which requires touching code that does anything.

| Catalog | Covers | Format |
|---|---|---|
| `packages/mirror-i18n/catalog/<code>.json` | backend events, shown in both apps | JSON |
| `desktopApp/src/i18n/locales/<code>.json` | desktop buttons, headings, tooltips | JSON |
| `mobileApp/lib/src/l10n/app_<code>.arb` | phone UI and its activity log | ARB |
| `mobileApp/android/app/src/main/res/values-<code>/strings.xml` | launcher label, notification | Android XML |

Use a [BCP 47](https://www.rfc-editor.org/rfc/bcp/bcp47.txt) tag for `<code>`:
`fr`, `pt-BR`, `zh-Hans`.

## Why the backend does not send sentences

Log lines from the Rust backend are rendered in the desktop app's activity
panel, so a *user* reads them. They used to be built with `format!` at the call
site, which compiled the English into the library and sent it across the FFI
boundary as finished prose — untranslatable at the only layer that knows what
language the user chose.

A call site now names a code and supplies parameters:

```rust
log_event!(codes::USB_STREAMING_OPEN_FAILED, "error" => format!("{e:?}"));
```

and the interface looks the wording up. The English rendering still travels
alongside as `message`, for the on-disk log file — which has to be readable
when someone pastes it into a bug report — and as a fallback for an interface
that has not been translated yet.

## Step by step

### 1. Backend events

Copy `packages/mirror-i18n/catalog/en.json` to `<code>.json` and translate every
`message`. Leave `level`, `component` and `action` alone: they are identifiers,
not text.

```json
"usb.streaming.open_failed": {
  "level": "ERROR",
  "component": "USB",
  "action": "streaming",
  "message": "Impossible d'ouvrir l'appareil : {error}. Connexion abandonnée."
}
```

Keep `{name}` placeholders exactly as they are — substitution is by exact name.
Move them around the sentence as the grammar needs; the order does not matter.

Then register the file in `desktopApp/src/i18n/events.ts`:

```ts
import frEvents from '@catalog/fr.json';

const EVENT_CATALOGS: Partial<Record<Locale, EventCatalog>> = {
  en: enEvents as EventCatalog,
  fr: frEvents as EventCatalog,
};
```

The Rust crate needs no change. It only ever emits codes.

### 2. Desktop UI

Copy `desktopApp/src/i18n/locales/en.json` to `<code>.json`, translate the
values, and add it to `LOCALES` in `desktopApp/src/i18n/index.tsx`:

```ts
export const LOCALES = {
  en: { name: 'English', catalog: en as Catalog },
  fr: { name: 'Français', catalog: fr as Catalog },
} as const;
```

`Locale` widens automatically, so `events.ts` will now accept `fr` as a key.
The app picks the closest match to the browser's language list on startup.

### 3. Mobile UI

Copy `mobileApp/lib/src/l10n/app_en.arb` to `app_<code>.arb`. Drop the
`@`-prefixed metadata blocks — they only need to appear in the template — and
change `@@locale`:

```json
{
  "@@locale": "fr",
  "appName": "Mirror",
  "statusWaitingForUsb": "En attente d'une connexion USB"
}
```

Run `flutter gen-l10n`. `AppLocalizations.supportedLocales` picks the file up on
its own, so `app.dart` does not change.

### 4. Android system strings

Copy `res/values/strings.xml` to `res/values-<code>/strings.xml` and translate
it. Android resolves the closest match itself; there is no code change.

Note the resource qualifier is not always the BCP 47 tag — regional variants
use `values-pt-rBR`, not `values-pt-BR`.

## What is deliberately not translated

**Logcat and the on-disk log file.** They are read by whoever is debugging and
quoted verbatim in bug reports. Translating them would make a pasted log harder
to search, not easier to read.

**Capture settings values** — `1080p`, `12 Mbps`, `Game + Mic`. They are sent
over the wire and parsed by `MirrorForegroundService.kt`. Only the labels
around them are translated.

**Event codes, component and action names.** Identifiers.

## Checks that will catch a mistake

- `cargo test -p mirror-i18n` fails if a code has no catalog entry, if the
  catalog has an entry nothing can emit, or if a placeholder is not
  lower_snake_case.
- `flutter test` fails if any `LogCode` resolves to empty text, or leaves a
  placeholder unsubstituted.
- A missing key in the desktop UI renders as the key itself — visibly wrong,
  and traceable straight to the entry that needs writing.
